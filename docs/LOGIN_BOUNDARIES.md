# 登录与管理访问边界（TASK-0036）

TASK-0036 明确解除 TASK-0035 的兼容性阻塞。本次有意改变两项既有公开 API：

| 入口 | 匿名/失效会话 | owner/admin/viewer |
| --- | --- | --- |
| GET /api/modules | 401，无元数据 | 200，既有响应结构 |
| GET /api/modules/{id} | 401，不泄露存在性 | 200；未知模块404 |
| /、/modules、/modules/:id、/settings | 转登录，页面不加载后台视图 | 可进入，按权限展示操作 |
| /users、用户管理/模块授权/注册策略与审核 | 401或登录跳转 | 仅有效owner且users.manage；admin/viewer403 |
| GET /api/health | 保留200/503探针 | 同左 |
| /api/auth/me、csrf、login、logout、registration-policy、register | 保留各自安全上下文与开关限制 | 不扩大原权限 |
| 显式public模块的业务/示例GET端点 | 保留原公开契约 | 同左 |
| assigned模块业务端点 | 保留401 | 仍需个人授权且模块启用 |

认证未配置或认证存储缺失时，元数据返回503，不能借此恢复匿名访问。开发docs/openapi仍只由既有显式开发开关控制，默认关闭；不新增公开端点。模块写入、审计、用户管理等原有后端权限依赖、Origin/CSRF和事务内身份复查保留。标准public模块router依然独立经过启停及只读边界，不能把metadata的认证当成public业务端点的认证。

匿名元数据客户端需适配有效同源会话；仅健康检查的客户端不受影响。原文档中public配置表示字段可安全展示，并不再意味着元数据可匿名获取。无数据库迁移或依赖变化；没有迁移真实数据库、读取真实用户/会话或重启已有服务。

前端统一由根组件确认会话后挂载工作台，仅在登录后读取模块列表和权限。首次确认或失败不显示后台内容；复查已确认会话期间保留身份，失败即清空。受保护API返回401统一清空身份、权限及后台资源，跳转登录；403表示权限不足，不冒充退出。浏览器重新聚焦/变为可见时复查会话。登录失败401不触发全局退出。会话失效只在后端响应或身份复查时可被观察，不宣称实时取消已在执行的请求。

登录目标通过returnTo查询参数保留，刷新登录页仍可返回。只允许已知工作台路由，拒绝外站、反斜杠、认证页循环及任意查询/片段；使用replace避免返回历史反复跳转。未授权/users只显示权限说明，不加载用户管理组件或请求用户列表。

注册开关关闭及查询失败时表单不显示；后端在写入事务内再次检查开关。公共注册接口404现在提示“注册服务暂不可用，请联系管理员确认后重试”，避免把旧后端缺接口的404误报为管理员的“申请不存在”。缺少0006表由现有后端安全返回503；本任务没有读取运行中服务的版本或真实schema来猜测现场原因。管理员审核接口404保留其列表上下文文案。无自动迁移或自动服务重启。

验证使用临时SQLite、受控PG CI及全API浏览器夹具。既有纯元数据/存储单元测试显式覆写认证依赖，只隔离原有注册表/持久化行为；新增真实会话测试不覆写依赖，覆盖匿名、owner/admin/viewer、过期、停用/撤销、跨源、CSRF和公开健康/注册状态。PG复用同一真实HTTP矩阵；public示例GET与assigned边界既有用例保留。最终实际检查结果见PR及协调状态。
