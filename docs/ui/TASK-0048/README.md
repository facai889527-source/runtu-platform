# TASK-0048 用户管理界面

当前迭代把用户管理改为目录与模态工作流，保留认证外壳和后端权限。

设计约束：沿用 Segoe UI / Microsoft YaHei UI，22px 目录标题、14px 账户名、12px 元信息；白色 #ffffff、画布 #f4f6f8、墨色 #263445、辅助文字 #647184、青绿 #176e66 与分隔 #e4e9ef。主张用账户行的清晰对齐建立秩序，不额外堆叠统计卡片。桌面为“账户 / 角色 / 状态 / 管理”四列，手机每行两层。目录负责加载/筛选/分页，UserCreate 负责创建，UserManage 负责账户草稿，UserModuleAccess 独立负责授权，UserDialog 仅负责模态生命周期。

- 中性浅灰画布、白色目录、青绿色主操作。用细分隔行承载账户、角色、状态和管理操作，替代重复的大型嵌套卡片。
- 搜索、角色和状态筛选只作用于当前已加载页，并明确标注“本页”；服务端保持每页最多 20 位的游标分页，没有全库搜索或虚构总数。
- 新建用户弹窗：默认普通用户，管理角色需显式核实，初始密码提交后清空，安全交接说明，不存储密码。
- 管理弹窗：账户资料与工具授权分为两页签；变更在同一弹窗中确认。当前账户角色/启停受保护，最后所有者与陈旧状态由原后端校验；授权使用已有 API 的 expected_granted 防止覆盖冲突。
- 原生 modal dialog 实现焦点隔离与背景不可交互；Escape/关闭/遮罩、滚动锁定、键盘页签、180ms 动效及减少动态效果偏好。请求未完成时禁止重复提交或关闭，超时后给出结果未确认提示。
- 同账户窗口焦点复核保留权限数据与表单；失败/撤权仍清除，身份变化清除旧权限与界面。设置页同样保留复核期间的草稿，避免焦点复核在策略提交时卸载表单；返回错误或撤权仍隐藏受保护控件。
