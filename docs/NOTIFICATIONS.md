# Telegram 消息设置：个人与公共 Bot（TASK-0054）

本版交付可使用的个人 Bot 与公共 Bot 私聊流程、加密存储和 owner 代管；不是独立基础模块。所有者直接绑定 Bot，管理员和普通用户显式选择公共或个人 Bot。“管理其他账户”默认收起，展开时读取对应 owner 数据。未部署或未启用时禁用不具备条件的操作，提供安全的不可用状态，不把前端更新当成后端启用。

**明确剩余产品范围：群组发现、成员过滤、owner 全群组可见性、多目标选择与逐目标去重尚未交付。** TASK-0054 明确允许优先个人 Bot/UI；群组需正式后续任务，不能输入任意 Chat ID 或伪装群组已可用。只接入真实注册申请事件，其他事件源保持关闭。

## 账户操作

所有账户包括 owner 初始无 Bot 模式、身份/chat、目标、订阅或启用。任选一种：

- **公共 Bot**：平台配置就绪后点击“使用公共 Bot”。无需 Token，但仍须完成私聊证明和主动选择私聊目标。平台配置不是对账户的自动绑定。
- **个人 Bot**：在 Telegram 的 BotFather 创建仅供本平台使用的 Bot。点击“绑定个人 Bot”，输入 Token，并确认对其拥有控制权、专供本平台且未被其他部署使用。后端通过固定 HTTPS getMe 检查 is_bot、ID/Token 前缀和用户名；getWebhookInfo 必须明确没有 webhook，否则拒绝接管。验证和持有 Token 证明的是访问控制权，不声称能识别 BotFather 原始创建者。Token 提交后立即从输入清空，取消、错误或离开页面也会清空；不写浏览器存储，不回显 Token。

个人 Token 使用 TASK-0052 的 Fernet/MultiFernet，连同平台账户 ID 放入认证加密封套，数据库只存密文。解密校验账户、密文、指纹和当前模式；密文换账户、密钥缺失/错误、Token/配置变化一律停止对应路由。每个 Bot ID 只能由一个平台账户持有，公共 Bot ID 也不能作为个人 Bot 占用。API 只返回安全模式、Bot 用户名、就绪布尔值和末四位身份；不返回 Token、密文、指纹或更新 offset。

### 私聊证明与测试

1. 选择 Bot 后点击连接，产生 256-bit 一次性 /start 链接，五分钟有效；数据库只保存摘要、发起会话/账户、目标账户和期限。
2. 由预期的 Telegram 身份在该 Bot **私聊**中点击 Start。私聊 chat ID 与非 Bot sender ID 必须同为正整数且相等、小于 2^52；群消息不能作为证明。
3. 公共与个人 Bot 均在页面点击“同步 Bot 消息”，经服务器持有的 Token 调用 getUpdates 读取；按当前模式、来源与挑战验证。
4. 接入只消费一次摘要并产生候选，**不绑定、不发送**。发起浏览器核对末四位，再以原登录会话和 Origin/CSRF 确认。owner 代管时只有发起 owner 会话能确认，目标账户不能顶替。
5. 确认后通知仍关闭、目标仍未选择。主动选择已验证私聊，选择支持的订阅并保存启用，才可测试。每五分钟最多一次测试，返回成功仅在 Telegram transport 确认发送后；失败暂停，未确认不要立即重发。

重复、过期、撤销会话、目标停用、owner 降权或 Bot/版本变化均拒绝旧结果。链接不进浏览器持久化或日志；外链 noopener noreferrer/no-referrer、响应 no-store。不要公开分享或让无关身份操作。当前保持私聊 ID 全库唯一，即一个 Telegram 身份只能绑定一个平台账户；冲突不透露占用账户。

## 个人 Bot 更新与独占边界

不自动注册/删除 webhook、不自动接管其他部署，也不运行背景长轮询。个人更新仅由明确的同步操作触发，getUpdates 使用 timeout=0、limit=20、仅 message；每批最多 20 个更新、64 KiB 响应，已提交 offset 之前的消息不重复处理。配对消息深度在队列中时可继续同步，页面不会谎称已读完所有历史消息。

同步前核查没有 webhook；HTTP 409 或已有 webhook 安全失败。每账户数据库租约带唯一 ID 和 30 秒期限，网络不持业务锁；提交时重新核实发起者、目标状态、绑定版本、Bot 指纹、租约所有权和期限。失败不消费挑战或推进 offset，旧请求不能清除替代租约。角色撤销、失效结果和错误批次都会回滚。

**无法证明外部程序完全没有轮询。** 操作员必须先在原部署安全停止轮询/webhook，用户需明确承诺独占；本平台不会为了成功而自动 deleteWebhook。没有冲突响应不等于已证明独占，凭据外泄后也不能保证其他持有者不会再次使用。原部署必须由其维护者处理。Telegram 无法枚举全部历史群组，本版尚不提供群组发现。

## Owner、权限与清理

所有启用账户可使用自助 `/api/me/notifications`；admin/viewer 仅自助。owner 通过独立 `/api/admin/notifications/users/{target}` 和次要的账户选择器管理其他账户，包括个人 Token 替换、重新加密、私聊证明、偏好、测试或断开。API 每次从数据库重新认证，网络结果和队列测试也重新核实当前 owner 权限；不扩大普通资料编辑权限。禁用目标可被 owner 检查、关闭或断开，但不可绑定/启用发送。viewer 无注册提醒权限，即使 owner 代管也不越权。

切换公共/个人模式或替换 Token 前先完成外部验证，提交时清除旧身份、目标、订阅、启用/暂停、挑战及个人密文，必须重新配对。验证失败保留旧配置，界面不声称已切换。断开无需密钥也可删除所有个人密文和清空上述状态。重新配对关闭投递并清除旧身份/目标/订阅；旧 revision 排队消息被丢弃。已进入网络请求的消息无法撤回。

## 运维：所有者初始化与本地升级（TASK-0056）

所有者首先直接绑定 Telegram Bot，不再选择公共/个人模式。确认其私聊证明后，该 Bot 成为其他账户可主动选择的公共来源；其他账户仍初始未绑定、未选择目标、未订阅。所有者断开或替换来源会撤销公共账户的旧路由与身份，必须重新选择和验证。所有者降权或停用也会阻止公共投递。

`POST /api/admin/notifications/setup` 仅允许当前所有者并校验 Origin/CSRF。它要求新架构已经存在，再初始化独立的服务器私有密钥文件并启用平台状态。默认文件为被 Git 忽略的 `secrets/telegram/store.key`；操作系统仅允许运行账户及 Windows SYSTEM 访问，权限保护失败即拒绝初始化。API 不接收或返回主密钥。既有显式环境密钥仍可用于受控轮换；错误密钥不会回退。密钥备份必须与数据库分离保管。

公共与个人 Bot 都可通过页面“同步 Bot 消息”获取一次性私聊证明；公共用户共用来源 Bot 的 offset 和数据库租约，不相互泄露候选身份。不要求最终用户配置 webhook、环境变量或迁移命令。页面已移除原“在哪里配置？”整块内容。

真实本地数据库目前停留在 `0007_login_activity`。升级到 `0012_owner_public_bot` 前必须取得所有者明确批准，并先验证 SQLite 一致备份及完整性。0008/0009 创建通知结构；0010 清空旧绑定、挑战并关闭旧订阅；0011 创建个人 Bot 密文表；0012 创建默认关闭且无公共来源的平台状态。不会导入环境 Token、初始化管理员或自动绑定账户。应用不会自动迁移。须以本任务实际操作记录确认备份和演练结果，不能把测试数据库迁移当成真实升级。

本次 API 与浏览器验证使用测试桩，不代表真实 Telegram 已连通。群组发现、成员过滤、多目标与逐目标去重仍待正式后续任务；页面明确显示当前不可用。


## TASK-0058：完整身份、并发证明与自定义测试

已连接页面使用紧凑概览，分别展示 Bot、已验证身份、目标/订阅及测试消息；首次绑定卡只在未选择 Bot 时出现。断开、替换、重新验证及重新加密置于次要操作，并需对话框确认，Escape 可取消。所有者依然直接绑定平台 Bot，其余账户主动选择公共或个人 Bot。

新迁移 `0013_telegram_identity` 仅增加账户和临时挑战的可空身份列，保存 Telegram sender ID、first_name、last_name 与可缺失/变化的 username。既有私聊证明要求 sender ID 等于 chat ID，迁移据此补齐已验证 ID，不清除绑定、凭据、偏好或公共来源；未知名称保持空。界面明确区分 Telegram User ID 和私聊 Chat ID，并支持复制。名称只作展示，绝不作为身份凭据。

每次配对使用独立256-bit随机链接、五分钟TTL、会话和账户作用域；只存摘要。业务互斥下原子消费一次，显示完整候选身份，网页勾选核对后提交确切 candidate_user_id。错误ID、旧会话、旧版本、过期/重放、错误Bot来源均拒绝。链接是短时持有证明，无法自动识别被转发给谁；用户必须核对完整User ID，不能盲目确认。单账户每五分钟最多5次创建，平台最多300次；同步仍受租约和原有限流约束，不能无限并发拉取。

共享来源使用一个Bot级租约和offset，网络阶段不持业务锁，提交前重查权限、版本、来源、租约和期限。每批最多20条，完整校验后按update_id排序；完全相同的重复只处理一次，同ID冲突整个批次回滚。一次同步可消费多个账户各自的证明，但只返回请求者身份。外部webhook/409仍拒绝接管；HTTPS回调还必须提供非空有效独立密钥，不允许空密钥绕过。

自定义测试只接收纯文本（可省略以使用默认文本），最大4096个UTF-16代码单元，拒绝空白、超长或控制字符。无需也不接受Chat ID或parse_mode；固定sendMessage使用纯文本发送到当前已验证、主动选中且启用的私聊。沿用Origin/CSRF、角色/目标授权、5分钟冷却、发送前再鉴权、队列上限和真实成功/失败判断。不保存或记录测试正文，不自动发送消息。

**本任务不执行真实0013迁移、不重启服务、不重新生成密钥、不更换Token、不改变现有真实绑定。** 已运行的0012后端会继续返回旧契约；新前端保留其现有连接展示，不编造完整身份，并禁用尚不具备的自定义消息能力。启用新后端和身份详情需要另行明确批准0013迁移及本地后端重启；不得复用TASK-0057的旧升级批准。群组、成员过滤、多目标仍未交付。
