# 后续能力路线图（规划，未实施）

本文件为 TASK-0012 的规划交付，不授权或实现下列功能。后续工作须另有正式 task_id/version、明确基线及验收，再由独立 PR 审查；不自动合并、部署或开放写入口。

## 当前已有能力

- FastAPI 工厂、只读健康检查、模块清单与详情；静态模块注册，禁用模块不挂载业务路由。
- 两项白名单公开配置模型与可选 SQLAlchemy/Alembic 存储服务。保存仅为 Python 内部服务接口，**没有对外管理写 API**。
- Vue 3 + JavaScript 管理后台、URL 导航、只读模块搜索/筛选/详情、加载/空/失败/重试、桌面与手机适配。
- 现有健康检查可描述数据库 not_configured/ready/unavailable。它不是完整监控、身份认证、审计或生产就绪证明。
- 目前产物在未合并的堆叠 PR 链中，不能因为本规划把所有能力视为已发布到 main。

## 推荐顺序与阶段边界

| 顺序 | 待开发能力 | 依赖与交付重点 | 建议验收门槛 |
| --- | --- | --- | --- |
| 1 | 身份认证、授权与审计 | 明确平台身份来源、会话生命周期、最小权限模型；定义哪些行为可查看/管理、审计事件与敏感数据边界 | 未登录/权限不足/过期会话均拒绝受保护操作；权限在服务端执行，跨用户/角色负例通过；关键身份和授权事件可追溯且不记录密钥 |
| 2 | 安全的管理写 API | 以阶段1为前提，先设计一小组明确白名单写契约、请求验证、错误语义、事务、冲突控制与审计，不批量开放内部服务方法 | 每项写操作有认证、授权、正负例与审计；重复/冲突请求行为明确；失败回滚，不允许越权字段或把私密配置返回前端 |
| 3 | 模块配置与启停 | 将已存在的静态状态与内部配置存储，按正式契约逐步提供管理操作；说明重启/重建应用或受控动态切换的边界，前端只呈现后端真实结果 | 配置白名单和版本/冲突约束稳定；禁用后路由/任务隔离可验证；持久化与运行状态不漂移，失败不显示保存/启停成功 |
| 4 | 模块扩展协议 | 在稳定的身份、写契约和生命周期基础上定义模块版本兼容、路由/权限/导航/迁移/任务声明及验证规则 | 示例模块通过契约测试；重复ID、权限缺失、不兼容版本、禁用与卸载边界明确；不得默认允许下载后执行任意第三方模块 |
| 5 | 部署与监控 | 明确环境配置、迁移操作、健康/就绪、备份恢复、回滚、日志和告警；在隔离环境验证后再申请实际部署授权 | 真实 PostgreSQL 在线迁移和恢复、部署回退/API代理、受保护入口、可观测错误与演练证据齐全；真实指标来自采集而非前端占位 |

### 为什么按此顺序

先知道操作者是谁、允许做什么以及如何追溯，再开放持久化变更；之后把配置和运行状态的一致性打牢，扩展模块才有可靠的权限和生命周期基础。部署与监控阶段负责在真实环境验证并交付运维方案，不能以当前本地构建/SQLite 测试替代。

阶段可以各自拆分成多个小任务和 PR，但前一阶段的关键边界应先通过审查。已有健康检查、迁移、内部配置服务可以复用，不需要把它们重新宣布为待开发；需要新增的是受保护的管理契约、在线验证和真实运行闭环。
