# TASK-0009 — Runtu Platform 管理后台 UI 第一阶段

## 基线与协作要求
本任务实现真正可用的前端管理后台 UI，不涉及认证或数据库写操作。当前 #3→#4→#5 是未合并堆叠 PR；#8 已确认 main+#5 隔离合并树无文件冲突，22 个 Python 测试和前端构建通过。**从远程 `codex/TASK-0005-persistence` 最新提交建立 `codex/TASK-0009-admin-ui`，新 PR base 必须为 `codex/TASK-0005-persistence`，仅呈现本任务 UI 增量。** 若父分支/正确 PR base 不可用，报告阻塞，禁止从 main 复制全链代码。任务幂等键 TASK-0009:9；先检查已有同任务 PR/记录。

## 产品目标与设计原则
构建具有长期扩展能力的 Runtu Platform 管理后台外壳。使用已安装的 `frontend-design`、`vue-best-practices` 作为设计/实现参考，但正式任务和 AGENTS.md 优先；保留 Vue 3 + Vite + **JavaScript**，禁止擅自迁移 TypeScript。界面语言以简体中文为主。追求克制、清晰、现代的 SaaS 管理后台风格：高质量排版、层级、留白、边界与对比，不堆砌装饰；避免直接复制第三方模板。提供统一 CSS 设计 tokens（颜色、字体、间距、圆角、阴影、断点、交互状态），适配深浅? **本阶段只需精致的浅色主题**，不要为暗色模式过度扩展。

## 必做页面和功能
1. 应用布局：左侧导航（品牌、仪表盘、模块管理、设置占位）、可折叠侧栏；顶部工具栏（当前页标题、后端连接状态、必要操作）；主内容区。移动端提供可关闭的导航抽屉/遮罩，保证不横向溢出。
2. 仪表盘：后端健康状态卡，数据库状态 `not_configured/ready/unavailable` 的明确中文说明，已注册/已启用/已禁用模块计数；模块概览和明确的空态。**只展示实际 API 返回的信息，不伪造流量、营收、告警、CPU/内存等指标。**
3. 模块管理：调用已有 `GET /api/modules` 显示名称、版本、分类、状态、能力摘要；支持前端本地搜索、状态筛选，列表与空态；点击进入详情，使用 `GET /api/modules/{module_id}` 显示真实 manifest/public_config，包含加载、404、503、失败及重试。禁用模块须明显标识；没有后端写 API 时，不渲染可误导的启用/删除/保存成功按钮。
4. 设置占位：清楚说明尚未开放管理配置（需未来认证授权），不要伪造可保存表单或登录。
5. 所有页面具备加载、空、网络失败和重试状态；请求应合理处理竞态与卸载，避免旧请求覆盖新视图。提供基本可访问性：语义标签、焦点可见、键盘可用、按钮名称、移动菜单 aria-expanded、对比度、减少动画偏好。
6. 合理拆分布局、页面、复用组件和 API client，避免把全部代码堆进 App.vue；不引入重量级 UI 框架、图表库、外部 CDN/字体/图像或额外遥测。可使用项目已有依赖；若确需新依赖，先说明理由并优先无依赖实现。
7. 与现有后端 API 契约兼容；不能修改后端路由语义或开放任何未认证写入口。可调整前端开发代理配置以便本地联调，但必须测试并说明。保留既有 health 和 modules 可用行为。
8. README/docs/DEVELOPMENT.md 补充页面功能、Windows 本地启动和限制。避免将未来功能写成已实现。
