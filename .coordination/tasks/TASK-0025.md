# TASK-0025 — 模块管理第一阶段：受控启用/禁用与配置基础

## 背景
用户已在本地真实 Chrome 确认：管理员 runtu (owner) 登录成功，Ctrl+R 刷新后仍登录，点击统一用户菜单退出正常回到登录页。此前 Codex TASK-0024 已验证匿名访问受保护接口 HTTP 401；**这不等于已经独立验证原会话 Cookie 在服务端注销后失效**。请在本任务状态摘要注明用户真实浏览器验收已完成，不要求用户重复登录；不要修改旧任务状态（协议默认仅写自身状态）。

## 目标
在现有 FastAPI + Vue 3 JavaScript + SQLAlchemy/Alembic、模块注册元数据、RBAC/CSRF 基础上，建设可用的模块管理最小闭环，而不是仅展示静态目录：
1. 先审计现有模块状态、配置模型、路由、权限、迁移和测试，写出最小改动方案，避免破坏模块注册与启用语义。
2. 实现仅 owner/admin（以现有实际权限策略为准，至少 require module.manage）的模块启用/禁用操作和必要的非秘密公开配置编辑。禁止任意代码执行、任意路径/文件编辑、插件包上传或未审核的动态安装。
3. 所有写操作服务端严格 RBAC、CSRF、会话校验、输入校验；保护核心/必需模块不被错误禁用，保持幂等与事务安全。viewer/匿名/CSRF 缺失必须拒绝。审计事件如现有模型支持则记录操作，勿记敏感配置。
4. 前端模块详情/列表展示清晰状态、受控操作、保存结果/失败提示、必要确认；隐藏或禁用无权限入口，区分无权限与功能尚未开放。避免开发期调试文案和重复身份栏。
5. 测试覆盖正常状态切换、未授权、CSRF、无效配置、幂等、失败回滚和重载后持久性；真实 PostgreSQL CI 能跑时沿用现有集成测试。数据库迁移必须可审查且不能自动对用户真实开发库做破坏性迁移。
6. 独立分支 + PR，不自动合并，不部署；按 .coordination/PROTOCOL.md 写 .coordination/status/TASK-0025.json。

## 安全边界
不要读取/输出用户密码、Cookie、CSRF token、密钥、.env、SQLite 内容；不重做 bootstrap、不重置管理员、不修改生产环境。优先兼容现有 API，不擅自引入大依赖。若现有模型不足以安全启用写入，先提交可审查的分阶段 PR，明确后续项，不制造假功能。TASK-0021/0024 历史状态不因本任务自动重跑或覆盖。

## 交付
PR、变更摘要、测试结果、权限矩阵、是否需要 Alembic 迁移、用户下一步动作；任务状态准确回传。
