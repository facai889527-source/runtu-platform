# TASK-0014 — 管理员身份认证安全基础（第一阶段）

## 任务目标
在 Runtu Platform 已有 FastAPI + SQLAlchemy/Alembic + Vue3 JavaScript 平台上，开发可测试、默认拒绝的**管理员登录/会话认证基础**，为未来 RBAC 和安全管理写 API 打基础。用户要求继续开发，但尚未授权合并/部署/开放业务写操作。本任务不得宣称已经完成生产级权限系统。

## 基线与幂等
幂等键 TASK-0014:14。先检查 GitHub 所有状态 PR 和同任务记录。产品最新父分支为 `codex/TASK-0012-ui-refinement`；从其最新 SHA 新建 `codex/TASK-0014-auth-foundation`，PR base 必须为该父分支，仅显示本任务增量。#13 是独立 main 文档/CI PR，不作为产品分支父级。若基线变更则停止并报告，不得擅自变基或合并。

## 安全要求（优先于 UI）
1. 在实现前阅读现有后端数据库迁移、配置、路由、公开模块 manifest、前端 API client 和测试，写简短威胁模型/设计决策文档。明确默认拒绝、会话边界、首次管理员引导边界、认证与授权区别、审计数据边界。
2. 使用成熟密码哈希库 Argon2id（或有充分理由的安全替代方案），只存哈希；登录校验避免用户枚举，固定安全错误消息，失败限速/锁定策略可测试。不要自己实现加密算法。依赖锁定与许可证合规。
3. 服务端 session 优先：随机高熵 session ID，数据库只保存 session token 哈希；HttpOnly Cookie，SameSite=Lax/Strict，生产 Secure 必须开启，开发环境的 HTTP 例外必须显式且仅 loopback；会话到期、登出撤销、服务端禁用用户后立即失效；不把 token 放 localStorage、URL、日志或响应 JSON。
4. 仅提供最小安全 API：登录、登出、当前身份、必要的 CSRF 获取/校验；所有有状态操作要求 CSRF 防护及 Origin/Host 合理校验；不开放未认证的管理写入。公开 health/modules/detail 保持现有契约和可访问性。对 `/docs` 和调试接口风险给出明确生产配置建议。
5. 首次管理员创建：**不得**提供公开网络的无认证初始化接口或默认用户名密码。优先仅本地受控 CLI/管理命令引导，交互式密码输入，不把凭据写命令行历史/日志；检查仅能初始化一次或需显式受控恢复流程。若无法安全完成则只提供设计/CLI占位，不冒险暴露注册入口。
6. 数据库表与 Alembic 迁移：用户、会话、必要的安全审计事件；索引、唯一约束、UTC时区和过期清理策略；SQLite测试兼容，PostgreSQL迁移注意事项。审计只记录安全事件元信息，不记录密码、Cookie、token、敏感请求体。
7. 前端提供与现有高品质设计一致的登录页和真实认证状态提示，但**不得**伪造已认证、写入权限或权限管理功能。未登录时仍可访问原只读页面（若原公开API允许），后台敏感能力未来才启用；清楚标注当前只读能力。网络失败/错误/限流有可理解反馈；禁止 localStorage 保存凭据。
8. 权限框架仅为未来扩展设计最小 `require_admin` / `require_authenticated` 依赖及默认拒绝的安全测试，**不得**将现有公共 GET 无意改成必须登录；也不得创建未经审查的配置编辑、启停、删除 API。
9. 遵循已安装 `python-testing-patterns`、`vue-best-practices`、`frontend-design` 的相关指导，不安装额外 Skills。允许必要且审查过的认证依赖，但不引入外部身份服务、短信/邮件、遥测、外部 CDN。所有配置经环境变量注入，仓库不提交真实秘密。

## 验证/交付
- 单测至少覆盖：成功/失败登录、未知用户同类响应、密码不出日志、session cookie属性、CSRF拒绝、无/过期/撤销session、禁用用户、重复引导拒绝、登录限速、匿名访问现有GET保持、缺少数据库时安全失败、迁移upgrade/downgrade风险说明。避免仅用模拟安全机制的假测试。
- Python pytest、Node tests、pnpm build、git diff --check；在可用环境用浏览器真实登录/退出冒烟，注意截图不能包含密码或 session；未跑则明确说明。真实 PostgreSQL 在线迁移若不可用须报告，不得称生产验证。
- `docs/AUTH_SECURITY.md` 写明部署前必做清单：HTTPS、Cookie Secure、可信代理头、CORS/CSRF、初始化命令、强密码、限流在多实例场景的限制、会话清理、备份恢复、生产部署禁止事项；标明第一阶段尚未实现 RBAC/权限管理/业务写API。
- 如安全实现规模过大，优先拆分成可验证的最小增量并明确剩余工作，不为了完成清单而牺牲安全。
- 不改其他PR分支、main、GitHub signal、AGENTS.md、Skills、runtu-github ACTIVE三分钟调度；不自动合并、部署或连接生产服务器；不提交 .env/.venv/IDE/node_modules/dist/真实凭据。
