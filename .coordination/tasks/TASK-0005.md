# TASK-0005 — 数据库基础与模块配置持久化（堆叠 PR）

## 基线与合并规则（必须遵守）
PR #3 仍开放、base=main；PR #4 仍开放、base=codex/TASK-0003-platform-bootstrap。TASK-0005 依赖 TASK-0004，因此从远程 `codex/TASK-0004-module-core` 的最新提交创建 `codex/TASK-0005-persistence`，新 PR 的 base 必须设为 `codex/TASK-0004-module-core`。不得从 main 创建导致重复 diff。若父分支不存在或无法创建正确 base 的堆叠 PR，报告阻塞，不擅自合并、变基或改写其他人的分支。以后 #3、#4 合并后再逐级调整基线。

## 目标
为 Runtu Platform 增加最小、可靠的 PostgreSQL 持久化基础与模块公开配置存储协议；不连接真实生产数据库、不增加业务模块。

## 范围
1. 引入 SQLAlchemy 2.x 与 Alembic，建立独立数据库会话管理、明确的迁移目录与初始 schema；数据库连接从环境变量读取，绝不硬编码凭据。保持应用可在没有数据库的本地开发环境下启动，/api/health 不得谎称数据库健康。
2. 设计模块配置持久化模型，采用模块 ID 唯一键，明确字段与默认值、更新时间；仅持久化明确允许的非敏感配置字段，禁止任意字典、明文凭据、token 和环境变量入库。
3. 为数据库连接、迁移、配置读写提供清晰服务层接口；本次可不暴露修改配置的 HTTP API，避免尚未有认证授权时产生公开写入口。原有只读 API 必须保持兼容。
4. 对配置保存增加校验、事务回滚、重复键及不存在模块的错误处理。考虑禁用模块的配置保留行为。
5. 使用 SQLite 临时数据库完成可重复的自动化测试；另给出 PostgreSQL 迁移步骤，说明 SQLite 测试不等于 PostgreSQL 已验证。如可用隔离 PostgreSQL 测试环境，可额外验证，不能假报。
6. 更新 .env.example（只有占位符）、README 和 docs/DEVELOPMENT.md 的本地启动、迁移、测试说明；保持 Windows/PyCharm 可用。禁止提交 .env、.idea、数据库文件、密钥。
7. Python 测试、前端构建、git diff --check 均需执行并在 PR 中报告真实结果；避免引入 Redis、Docker、登录、复杂 RBAC、生产部署。
8. 不修改现有 Codex `runtu-github` 三分钟 heartbeat；不自动合并 PR、不提交 main、不部署。
