# TASK-0022 — Runtu 后台信息架构与登录页重构

## 背景及任务衔接
用户已在本地浏览器真实使用管理员 runtu 登录，截图显示 owner 身份和权限；随后点击退出登录，截图显示匿名浏览及独立登录表单，但登录页仍嵌套后台侧边栏和面包屑。截图也证实仪表盘、模块管理、设置页重复展示登录/只读状态和页面内退出按钮。用户明确要求重新区分登录与后台布局。TASK-0021 的 GitHub 状态仍是 blocked_user_action；本任务不能擅自把它标记 completed，刷新保持登录及退出后受保护 API 拒绝仍需独立核验。不要索取、读取或打印用户密码、cookie、session、csrf 值。

## 目标
构建正式管理后台的信息架构和更紧凑专业的视觉层级，不是仅改颜色：
1. 登录路由 /login 采用**完全独立的认证布局**，不显示后台侧栏、后台面包屑、后台刷新按钮、后台连接状态或重复“管理员登录”按钮。登录表单居中或合理双栏，简洁品牌、明确标题、用户名/密码、错误提示；登录后进入后台。已登录访问 /login 应合理跳转。
2. 登录后的应用壳统一：左侧可折叠导航、顶部面包屑及右上角用户头像/名称下拉（含角色、个人资料占位/安全入口视实际能力、退出登录）；**退出登录只出现在统一用户菜单**，不在各页面正文重复。响应式桌面与窄屏合理布局。
3. 仪表盘以业务信息为核心：健康/模块汇总/模块概览，删除重复认证身份、权限胶囊、每页“匿名浏览/当前只读”等开发调试信息。健康详情放到适当专用区域或精简状态卡，顶部连接状态避免冗余。
4. 模块管理提供清晰的目录、搜索/筛选、模块卡片/详情层级；设置尚未开放时简洁诚实地说明，不造假可编辑功能。区分 **owner 角色权限** 与 **功能尚未开发/当前页面只读**，不要让 owner 误以为被降权。不要无依据增加“用户管理/审计日志”等未实现可点击功能；未实现导航应隐藏或明确禁用。
5. 避免大段重复说明、过大留白、页面顶部重复标题；保持统一组件、间距、响应式及无障碍键盘交互。

## 安全与工程边界
保留 Vue 3 JavaScript、Vite、现有路由/API/真实身份与 RBAC、CSRF、HttpOnly session 及 logout 行为；绝不模拟登录、绕过权限或删除只读限制。不要触碰本地 SQLite/.env/管理员引导，不部署生产。使用现有设计约定；如可用遵循 frontend-design、vue-best-practices。开发改动使用独立分支及 PR，跑 frontend tests/build 和相关后端认证回归，勿自动合并。遵守 .coordination/PROTOCOL.md 写入 .coordination/status/TASK-0022.json，准确区分自动测试与用户真实浏览器验收。

## 验收
/login 无侧栏且登录/退出流程可用；已登录页面只在统一用户菜单显示身份及退出；仪表盘、模块管理、设置页面不再重复展示认证调试信息；视觉信息层级明显改善；权限/安全行为保持；测试通过并提供 PR 供审查。
