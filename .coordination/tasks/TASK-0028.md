# TASK-0028 — 模块操作记录查询与后台审计界面

## 背景
TASK-0027 已完成本地隔离开发 SQLite 0004_module_management 迁移并重启后端，管理员 owner 与原数据保持，前后端可用。模块启停和公开配置编辑已在 PR #20 合并并测试。module_changes 表现已记录模块变更，但缺少供管理员查看的可审计 UI。

## 目标
1. 先检查现有 module_changes 记录字段、RBAC audit.read、现有管理页面和测试。设计最小安全查询 API：按模块过滤、分页/限制条数、稳定排序、固定字段输出；禁止任意 SQL、无界导出、暴露凭据或敏感配置。
2. 只允许具备 audit.read 权限的身份读取操作记录；匿名和 viewer 按现有权限矩阵拒绝。确保 owner/admin 视现有策略可读。列表仅展示操作者可公开的标识、模块、操作类别、时间、revision；不得返回会话、token、密码哈希或配置秘密。
3. 在模块详情提供“操作记录”区块或入口，适当展示最近变更、加载状态、空状态、权限不足及分页。界面简洁，避免重复身份栏、调试信息。可以先做模块内审计，不必搭建复杂的全局日志平台。
4. 后端及前端测试覆盖权限、分页边界、过滤、排序、无记录、记录来自真实事务且失败回滚不留记录；生产构建通过，必要时运行隔离浏览器夹具。若有 PostgreSQL CI 则纳入。
5. 先检查是否需要 Alembic 迁移；尽量复用 0004 结构，避免对用户开发 SQLite 进行不必要 schema 变更。不要操作真实用户数据库数据、管理员账户、凭据或生产服务。
6. 独立开发分支和 PR，禁止自动合并；按 .coordination/PROTOCOL.md 写 .coordination/status/TASK-0028.json，报告权限矩阵、测试、PR 和用户下一步。

## 安全
本任务允许读代码和在隔离测试库执行测试；不得读取/输出用户真实模块审计数据、凭据、Cookie、数据库 URL。不要自动迁移真实开发库、重启无关进程或部署。若发现安全问题先在 PR 里修复并报告。
