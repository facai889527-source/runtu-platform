# TASK-0012 — 管理后台视觉精修、信息密度与模块目录适配

## 背景与目标
用户审阅 TASK-0011 的七张实际桌面/手机截图，认可墨蓝侧栏、统一图标、KPI、模块信息分组比旧版成熟，但仍有细节不足：辅助字号过小、桌面仅一模块时右侧大片空白、卡片节奏/状态/操作入口和手机工具栏仍可精修。本任务是**高质量精修，不重做设计方向**，并为多模块规模化展示做准备。

## 基线
先检查远程 GitHub 最新 PR #11、已有 TASK-0012 PR 与本地幂等记录（TASK-0012:12）。从最新 `codex/TASK-0011-premium-ui` 创建 `codex/TASK-0012-ui-refinement`，新 PR base 为 `codex/TASK-0011-premium-ui`，只展示本任务增量；若父分支变更/不可用，报告阻塞，不得复制堆叠或更改原分支。

## 必须完成
1. 设计系统排版精修：检查桌面1440、1280、手机390和360下的正文/辅助文字、导航/表单/页脚。重要辅助说明建议不小于12–13px，普通正文14–16px；按视觉角色合理设置字重/行高/对比度，不盲目全局放大造成拥挤。所有交互按钮/链接保持清晰可读、焦点明显。
2. 模块管理自适应目录：只有1个模块时页面布局不显得残缺，2–4个和8+个模块时网格能自然扩展，使用CSS Grid auto-fit/minmax 或经论证的布局；不同长度模块名、版本、能力摘要应换行/截断合理，避免卡片高度失控。**实际默认后端只有一个demo，不得为正式页面伪造模块**。多模块场景只能用明确标记的浏览器网络夹具验证。
3. 改进模块目录搜索与筛选区的信息层级、宽度、空态、状态提示、卡片可点击区域和hover/focus；保持既有搜索、筛选、路由、详情与返回时筛选保留。
4. 仪表盘：对健康/数据库提示与KPI间距做细致统一，处理数据库 not_configured/ready/unavailable 的语义；不要把未配置当健康正常的数据库，不得虚构指标。优化模块概览在0、1、多个模块时的信息密度。
5. 模块详情：元信息、公开配置、只读说明进一步优化阅读顺序、文字大小、长值断行和窄屏；不新增编辑/保存等假操作。
6. 手机顶栏：390和360宽度下刷新按钮、连接状态、标题和抽屉按钮的排列合理；触控目标尽量44px，必要时将次要状态移到第二行但避免无意义空白；检查安全区域和横向滚动。
7. 统一状态徽章、图标、按钮、表单边界、卡片圆角/阴影/分隔与页脚细节；维持 TASK-0011 墨蓝/冷白/翡翠绿设计方向，不添加外部字体/CDN、沉重组件库或无功能装饰。
8. 对主要界面做一次简短的无障碍检查：键盘导航、焦点可见、语义、prefers-reduced-motion、正文/次文对比度；对发现的问题做最小修复，不能把自动对比度测试当成完整WCAG审计。
9. **额外仅出规划**：在 docs/ROADMAP_NEXT.md 给出平台后续能力的推荐顺序（身份认证/授权与审计 → 安全的管理写API → 模块配置/启停 → 模块扩展协议 → 部署监控），区分已实现与待开发；本任务不实现认证或写API。
