# TASK-0016 — PostgreSQL 真实迁移与认证/RBAC 集成验证（不开放写业务 API）

## 背景
Runtu Platform 的产品分支现已堆叠至 PR #15（#3→#4→#5→#9→#10→#11→#12→#14→#15）。#15 已实现 owner/admin/viewer 固定 RBAC 与 GET /api/admin/me，但迄今只有 SQLite 在线测试和 PostgreSQL 离线 SQL 检查。数据库真实迁移、认证事务与并发语义尚未验证。**本任务优先补齐这项上线前关键证据，而不是继续堆叠新管理写接口。**

## 基线/协作
幂等键 TASK-0016:16。先检查 GitHub 最新 PR #15 head、全部状态 PR 和同任务 PR/记录。从 `codex/TASK-0015-rbac-foundation` 最新 head 创建 `codex/TASK-0016-postgres-validation`，PR base 指向该父分支，只包含本任务增量。若父分支不可用或变更，报告阻塞；不自动合并、改 base、变基、强推旧 PR。

## 实施
1. 详细审查现有 Alembic 0001/0002/0003、SQLAlchemy 配置、会话和限流、审计、RBAC 迁移逻辑。梳理 SQLite 与 PostgreSQL 的类型/默认值/约束/事务/时间戳差异，列出必须验证的高风险点。
2. 在可用时启动**隔离、一次性** PostgreSQL 测试实例（优先已有本地 Docker/容器能力；不得连接生产或未知数据库、不得开放公网端口；凭据仅临时注入，不写入 Git）。若 Docker/PG 不可用，**不安装系统服务、不使用外部云数据库、不请求真实生产凭据**；只添加可选的测试工具/说明和明确阻塞，不伪称已做在线验证。
3. 添加可重复执行的 PostgreSQL 集成测试/脚本（使用单独测试库和明确安全护栏，绝不能对非测试数据库运行破坏性迁移）。覆盖 0001→0002→0003 upgrade、schema/index/unique/check约束、旧管理员→owner、session 撤销、三角色授权、并发首次初始化、登录失败限流的原子性、UTC/时区、审计记录无秘密、禁用用户立即失效；可行时覆盖降级/重升级的风险，但必须仅在一次性库内进行。
4. 审查实际实现是否存在 PostgreSQL 方言/并发缺陷。若发现缺陷，在本任务分支做**最小、可测试**修复并说明兼容 SQLite 的影响；不能为通过测试而降低认证/CSRF/Origin/权限安全要求。
5. 将测试接入独立可选流程（例如 `scripts/test_postgres.py`、pytest 标记或本地 compose 测试文件），默认 `pytest` 不应因为缺少 PostgreSQL 而失败。测试工具不得误连默认数据库、不得打印连接密码或会话秘密。不要改已有 #13 CI PR 的工作流；可在文档建议未来合并后如何扩展 CI 的 PG service。
6. `docs/POSTGRES_VALIDATION.md` 写明运行命令、数据库隔离护栏、实际执行环境和结果、未验证事项、生产迁移前备份/维护窗口/回滚策略，尤其 0002/0003 降级会丢认证/角色数据，不能将降级当作无损回滚。
7. 现有公开 GET、管理员登录/退出、CSRF、RBAC、前端界面不回归。**不新增模块启停、配置编辑、用户管理、角色编辑等业务写端点。** 不修改插件执行隔离设计以外的范围。

## 验证与限制
- Python 全量测试、Node 全量测试、pnpm build、git diff --check；若 PG 实例可用，报告真实 PG 版本、运行方式、测试项与结果，并清理测试资源；否则明确未运行。
- 检查新脚本的安全性：必须只接受明确标记的测试 DB，阻止默认/生产连接，清理只删除自己创建的资源；不得泄露 DSN/密码到日志、PR、截图。
- PR 写明实际证据、修复、未覆盖风险和后续建议。
- 不修改 main、其他 PR、AGENTS.md、Skills、GitHub signal、runtu-github ACTIVE 三分钟任务；不合并/部署、不碰生产服务器，不提交 .env/.venv/node_modules/dist/秘密。

## 验收
得到可重复的 PostgreSQL 在线集成验证路径，能明确证明或诚实报告认证/RBAC 迁移和事务行为在真实 PG 上的兼容性，并为后续安全管理 API 提供可信基础。
