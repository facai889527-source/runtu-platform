# TASK-0020 — GitHub 双向协作状态回传与任务交接

## 任务背景
用户明确指出：此前 ChatGPT 通过 GitHub `.coordination/tasks/TASK-XXXX.md` 和 `.coordination/signal.json` 下发任务，Codex Windows 自动化执行后却只在本地对话回复，导致用户不得不复制结果回 ChatGPT。**修复此断点优先于新业务模块开发**。TASK-0019 的真实结果由用户转述：隔离开发库 `secrets/local-dev/runtu-dev.sqlite3` 已迁移到 `0003_rbac_roles`，被 git 忽略，健康/匿名身份/CSRF/未授权拒绝通过，75 Python passed/5 PG skipped、12 Node passed/build，临时服务关闭；因非 TTY，管理员尚未创建、真实登录未验收。不得把 TASK-0019 标记 completed；应标记 blocked_user_action/awaiting_interactive_input，已完成的准备步骤单独标注。

## 目标
设计并实际实现 **Codex -> GitHub -> ChatGPT 的状态回传协议**，使后续用户无需手动转发任务完成报告。任务本身应由本地 Codex 自动化领取执行，并把状态写回 GitHub；ChatGPT 可读取已知路径获知进展。

## 协议及实现
1. 审核现有 `.coordination` 目录、现有 `runtu-github` 自动化任务的执行说明/代码和已有协议，优先兼容原机制，不要假定能自动编辑 Codex 桌面内置自动化配置。如果无法由仓库指令自动让调度器执行新协议，必须说明需用户在自动化配置中进行的最小一次性变更，不可虚报已接入。
2. 为每个任务提供独立状态文件：`.coordination/status/TASK-XXXX.json`，建议字段 `task_id`, `signal_version`, `state` (queued/running/blocked_user_action/completed/failed), `updated_at` (UTC ISO8601), `summary`, `checks`, `blockers`, `branch`, `pr_url`, `commit_sha`, `next_action`。文件只能包含非秘密信息，不允许密码、数据库凭据、Cookie、CSRF、令牌、私有环境变量、个人路径/用户名等。可写精简中文总结。禁止把 `.env` 或 SQLite 数据库提交 GitHub。
3. Codex 在领取任务时回写 running；关键阶段或遇到需要用户输入时回写 blocked_user_action；结束时回写 completed/failed，带测试结果与 PR URL。对于任务只做本地操作而无 PR 的情况，仍必须回写状态。首次落地时为 TASK-0019 写**准确的历史状态**，标注真实登录未验收且等待用户安全交互；不要伪造成功。也为 TASK-0018 补写完成状态（根据已有可核实执行记录）。
4. 采用最小权限与并发安全：状态写回只允许修改自身任务状态文件；不通过状态回传修改 `signal.json` 或任务正文。处理 GitHub main 分支并发更新/冲突，避免强制推送、重置或覆盖用户代码；推荐 GitHub Contents API 按 SHA 乐观并发或临时工作树/安全分支+PR。**不要因状态回传触发本地 main 同步或数据库迁移**。若 Codex 无权限直写 GitHub main，则用固定状态分支/PR 并说明 ChatGPT 需从该位置读取，不能静默丢失结果。
5. 写一份简洁的 `.coordination/PROTOCOL.md`，说明任务信号是 ChatGPT->Codex，状态文件是 Codex->ChatGPT，幂等、状态机、失败重试、阻塞和凭据保护；配轻量校验脚本/测试（如有必要）。要让**后续自动化每次领取任务时遵循回传协议**，而不只是这一次写两份文件。
6. 验证：至少一次由 Codex 实际写入状态并从 GitHub 读取确认，模拟重复运行不会重复执行危险操作，保证不会泄露秘密或意外修改产品代码。产出中文结果，报告状态文件路径、是否真正自动回传、是否需要一次性修改本地自动化配置。

## 安全限制
- 本任务不授权自动管理员引导、不要求用户在聊天发送密码。TASK-0019 保持等待真实交互 TTY 的状态。
- 不自动部署、不重置数据库、不 force push、不删除分支、不擅自改 `runtu-github` 调度频率、不修改任何秘密。
- 如需要改自动化本身的任务说明，先判断是否可在当前本地环境安全操作；不可操作则明确告知用户。
- 若要改仓库产品代码，走单独 PR；协议/状态文件可依当前已授权的协调文件工作流提交，但避免冲突并核实远端结果。

## 验收
GitHub 上能看到真实的 TASK-0019 阻塞状态及 TASK-0020 执行状态；之后每个任务都自动回写状态，ChatGPT 可以直接读取，不再要求用户手动转述 Codex 报告。
