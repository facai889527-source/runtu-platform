# TASK-0011 — 管理后台高品质视觉重设计（Design System v2）

## 用户反馈（最高优先级）
用户审阅 TASK-0009/0010 的桌面与手机截图后明确指出：“这个UI界面确实不好看，没有那么现代化，看起来不是很高级”。现有界面是大片浅灰背景、简陋侧栏、线条分割的三数字统计、占空间的健康提示、表格式模块详情、移动端简单缩窄。**本任务必须显著提升视觉品质，不是微调边框颜色。**

## 基线/流程
先检查最新 GitHub 状态、同任务 PR 和幂等记录 TASK-0011:11。从最新 `codex/TASK-0010-routing-polish` 建立 `codex/TASK-0011-premium-ui`，PR base 为 `codex/TASK-0010-routing-polish`，仅本任务增量；若基线变化，先报告。保留 TASK-0010 的 URL、前进后退、详情、移动抽屉、真实只读 API、错误/空态。不要修改任何现有 PR 分支或自动合并。

## 设计方向
打造专业、现代、辨识度高的 SaaS 管理控制台：**精致、清爽、有秩序、信息密度适中、细节考究**，不做浮夸渐变/大面积装饰/拟物/模板拼贴。可采用偏中性暖灰/冷白底色、深墨蓝文本、深翡翠绿或蓝绿品牌点缀；颜色应形成有主次的系统。可设计更有质感的 Runtu 品牌字标/图形标记（CSS/SVG 本地实现），不依赖外部字体、图片/CDN。使用系统中文字体栈，处理字号、字重、行高、数字等宽、icon 风格一致性。浅色主题优先。

## 具体改造
1. 重新设计应用 shell：侧栏宽度与层次、品牌区、导航图标、激活态、底部区域；顶部栏整洁，有合理分割和操作层级；桌面/移动端视觉一致但布局分别优化。不要放没有功能的铃铛/头像/搜索。
2. 仪表盘：将健康状态做成信息紧凑但有辨识度的状态卡/运行摘要，数据库未配置的警示要诚实、可理解；模块注册/启用/禁用三项做成真正设计过的 KPI 卡片，数字/标签/图标有节奏；模块概览改为清晰的模块条目卡或高质量列表，避免空白大块。
3. 模块管理目录：优化搜索、筛选、计数、状态标签、模块条目、交互 hover/focus/disabled，支持长名称和窄屏；保留真实功能。
4. 模块详情：把“模块信息”和“公开配置”变成有层次的两组信息区块（例如信息网格、描述列表、配置说明卡），不再只是横线表格；处理长值换行和空值；明确只读。
5. 移动端：390px 与 360px 均应无横向溢出，标题、KPI、状态、详情信息重排；顶部工具栏不拥挤，触控区域合理；抽屉有质感并支持 Escape、焦点管理。
6. 统一设计 tokens：色板、字号、间距、圆角、边框、阴影、焦点、状态；必要时重构 CSS 和复用视觉组件，但不进行与 UI 无关的代码大重写。动画克制且尊重 prefers-reduced-motion。AA 对比度尽量满足，键盘焦点清晰。
7. 提供至少 2 个有实质差异的视觉方向的简短设计论证（文档/PR 中可写比较），选一个完成度最高的方向实现；**最终实际实现必须是一套一致的设计**。可调用已安装 `frontend-design` 和 `vue-best-practices`，不安装其他 Skills。不得仅修改文档而不实现页面。
8. 不伪造图表、流量、营收、运行时指标或数据库连接；没有 API 就不加假功能；保持 Vue3 + JavaScript、现有 API/路由/测试行为，不引入重量级 UI 框架、外部资源、未授权写入口。
